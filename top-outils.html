Présentation générale

Ce projet s'appuie sur un ensemble réduit d'outils soigneusement sélectionnés pour leur complémentarité. Chacun occupe une place précise dans la chaîne : Hermes Agent pour le runtime d'exécution autonome, Opencode pour l'assistance au développement, Claude pour le raisonnement et la planification, et GitHub pour l'hébergement et le versioning du code.

Hermes Agent

Démon système d'arrière-plan qui pilote l'exécution des agents autonomes. Contrairement à un LLM qui se contente de planifier, Hermes Agent exécute concrètement les opérations géospatiales via des outils déterministes.

  • LLM vs Hermes : le LLM planifie (il génère du texte, pas du code exécutable) ; Hermes exécute (il appelle PyQGIS, GDAL, PostGIS et valide chaque paramètre avant transmission au système hôte).
  • Runtime persistant : disponibilité 24/7, asynchronisme, persistance contextuelle — idéal pour les tâches longues et les jobs planifiés (Cron).
  • Trois endpoints : /v1/chat/completions (stateless), /v1/responses (stateful), /v1/runs (asynchrone).
  • Apprentissage via Skills : conforme à la norme open-source agentskills.io. Chaque séquence d'opérations réussie est consignée comme une compétence réutilisable, publiée sur le Skills Hub et immédiatement utilisable par l'ensemble des agents de l'équipe.
  • Sécurité : authentification Bearer (API_SERVER_KEY) et cloisonnement par X-Hermes-Session-Key.
  • Garde-fous : plafonnement des sorties d'outils à 2 000 caractères (history_tool_output_max_chars).
Rôle · Runtime d'agent autonome

Opencode

Agent de codage qui assiste le développement en générant, modifiant et validant du code source. Il pilote les sessions d'agents IA pour produire des scripts géomatiques et des fichiers de configuration de manière reproductible.

  • Assistance développement : génération de code Python, shell et fichiers de configuration.
  • Orchestration : pilotage de sessions d'agents IA indépendantes pour éviter les biais méthodologiques.
  • Révision de code : analyse neutre de l'architecture, détection des redondances et observabilité.
  • Intégration : utilise les modèles locaux (Ollama) ou distants selon les besoins de traitement.
Rôle · Agent de codage & orchestration

Claude

Modèle de langage de grande taille utilisé comme centre de planification cognitive. Il traduit les intentions en langage naturel en pipelines de traitement géospatial structurés, sans exécuter lui-même les opérations.

  • Planification cognitive : transforme une demande métier en plan d'action structuré et explicite.
  • Séparation plan / exécution : Claude planifie, les outils exécutent (règle architecturale centrale).
  • Raisonnement géospatial : interprète les relations topologiques, les CRS et les contraintes spatiales.
  • Routage : modèle léger pour les opérations simples, modèle plus performant pour les raisonnements complexes.
Rôle · Planification cognitive (LLM)

GitHub

Plateforme d'hébergement de code et de gestion de versions. Elle sert de dépôt central pour le manuscrit, les scripts de déploiement, le site de documentation et les fichiers de configuration du projet GisAI.

  • Versioning Git : historique des modifications, branches de développement et revues de code (pull requests).
  • Hébergement : stockage du manuscrit PDF, des images du manuel et des sources du site web.
  • CI/CD : déploiement automatisé et tests d'intégration via GitHub Actions.
  • Collaboration : issues, discussions et suivi des tâches liées au développement de l'assistant géomatique.
Rôle · Hébergement & versioning
